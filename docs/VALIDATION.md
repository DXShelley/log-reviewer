# 初版验证记录

日期：2026-10-14。主机：Windows 10 专业版 10.0.19045、Intel Core i7-10750H @ 2.60GHz、amd64；Go 1.25.3。

## 大文件实测

通过 `tools/bench` 实际写入文件，再流式分析。结果包含扫描、分类、索引写入及内存中的摘要生成，不包含浏览器启动、上传/复制文件和 JSON 报告下载时间。

| 样本 | 实际字节 | 分类耗时 | 匹配事件 | 分类数 |
| --- | ---: | ---: | ---: | ---: |
| 1 GiB 混合文本 | 1,073,741,824 | 1.563 秒 | 769,984 | 2 |
| 1 GiB 全 ERROR 文本 | 1,073,741,824 | 5.048 秒 | 7,561,562 | 1 |
| 10 GiB 混合文本 | 10,737,418,240 | 23.197 秒 | 7,699,835 | 2 |

混合样本约 88% INFO、10% ERROR、2% WARN，使用重复 Spring Boot 风格模板；数字时间与消息结构相同。文件刚生成，操作系统缓存可能参与，**不是冷缓存磁盘基准**。模板重复会受益于指纹缓存，不代表所有真实日志的速度。全 ERROR 样本额外测试了约 288 MiB 索引写入压力。

Go `runtime.MemStats` 的分析结束时 heap 为约 3.2–3.8 MiB，runtime sys 约 11.4–15.6 MiB；这些不是 Windows 进程峰值 RSS，不可当作整进程最大内存。多分类、长堆栈和 JSON 解码会增加内存及时间。

在这些文本样本中满足 1GB/10秒目标，并验证了 10GiB 打开/分类。尚未对所有 JSON 格式、自定义正则、大量唯一分类、慢磁盘或冷缓存证明统一 10 秒上限。

原始结果在 `docs/bench-results/`；复现使用：

最终交付 Windows 二进制在项目目录重跑同一 1GiB 混合文本，分类耗时 2.094 秒、769,984 个事件、2 类。与首轮测试存在运行条件差异，仍低于 10 秒。

```sh
go run ./tools/bench --dir <临时目录> --gib 1
go run ./tools/bench --dir <临时目录> --gib 1 --dense
go run ./tools/bench --dir <临时目录> --gib 10
```

## 功能检查

`go test ./... -count=1` 与 `go vet ./...` 已通过。覆盖：

- Java 深层 cause 聚合、完整堆栈、上下文与原始导出。
- Python traceback 关联同一日志事件，避免重复计数。
- 文本 / JSON / Pino / Serilog / glog / panic / ANSI / BOM 格式。
- 整数和小数 Unix 时间，毫秒/微秒/纳秒精度。
- 多文件归类、路径去重、报告落盘与重新加载。
- 时间窗口、关键字、逐行正则、无效表达式和逆序时间范围。
- 超长物理行、超长堆栈、2 MiB 预览截断与完整导出。
- 源文件修改检测、UTF-16 明确拒绝、损坏索引拒绝。
- 防止报告/导出覆盖源文件或硬链接别名。
- HTTP token、Host/Origin 校验、完整 API 工作流、上传与分页校验。

`go test -race ./internal/...` 在本机以 `0xc0000139` 退出，未完成 race 验证；普通纯 Go 构建和测试不受影响，不能据此声称 race 检查通过。

## GUI 检查

Playwright 连接 Chrome 154 的独立 CDP context，验证 1440×980 和 390×844 视口：文件选择、多文件分类、Java 堆栈、上下文、复制请求、分类导出、JSON 报告导出、关键字、正则错误、时间范围、级别筛选、文件导入与无横向溢出。页面 JavaScript 异常为 0。

本机 clipboard API 写入成功但读回为空，独立最小页面的 `writeText` 和 `execCommand('copy')` 同样如此。已验证正确复制内容传入 API，并加入写回检测（已有读取权限时）、选中文本弹窗和文本下载兜底。**本机系统剪贴板持久写入没有验证通过**；不将这一项伪装成成功。其他机器正常剪贴板 API 可直接复制。

截图和自动检查结果在本地 `reports/`，测试脚本为 `tests/gui-smoke.cjs`；最小剪贴板诊断为 `tests/clipboard-check.cjs`。
