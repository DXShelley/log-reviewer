# 工作区与时间片段导出

## 文件与布局

Windows 本机直连工具时，“导入文件”使用系统选择器，支持多文件或目录，保存源路径后只读分析，不复制日志。本机来源按实际连接的 loopback 或本机网卡 IP 判断，不信任转发头。导入目录包含子目录中的普通文件，最多 10000 个，不跟随目录符号链接；“输入路径”的目录规则仍为当前层日志。拖入文件时也会打开系统选择器以获取真实路径，因为浏览器不会暴露拖入文件的绝对路径。其他系统本机访问时引导使用“输入路径”；远程浏览器导入访问机器上的文件会生成上传缓存，也可使用“输入路径”直接读取工具机器的文件。正在分析或导入期间不接受新拖放。反向代理可能让服务端将来源判断为本机，代理部署请使用输入路径，避免在服务器上打开系统窗口。

源日志只通过只读接口打开，分析、搜索、详情和导出均不修改源文件。索引、报告和上传缓存写入临时会话目录；远程下载及回退缓存写入“文件设置”指定的保存目录。修改保存目录会自动迁移已有文件并保留分析可用性，系统默认路径见 [SFTP 说明](sftp-usage.md#保存目录与文件名)。远程默认通过 SFTP 直接读取，仅连接中断、超时等网络错误触发缓存重试；源文件变化、认证或权限错误需修正后重试，不自动复制。普通 `fetch` 命令与旧版 API 的显式下载仍是下载操作。

网络异常后的缓存属于本次远程源的快照，后续详情、搜索和时间片段导出复用该缓存，缓存完整时即使远端断开也能继续读取，不再反复下载。此时不会持续监控远程文件变化；需要最新日志时重新预览并获取。正常直读仍要求远程主机可连接。导出的 JSON 报告不包含连接凭据，工具重启后不能仅凭报告恢复远程访问，需要重新连接并分析。

GUI 的系统选择器、输入路径、浏览器上传、粘贴及远程获取共用导入规则：先按完整内容的 SHA-256 与当前分析列表比较，相同内容跳过，不因名称或路径不同重复加入；不同内容同名时提示覆盖、保留并重命名或取消。默认名称如 `app (1).log`，也可手动指定。覆盖仅替换列表条目，直读重命名仅改变列表显示别名；悬停仍显示原始来源路径，不覆盖、删除或重命名源日志。显示别名属于当前页面状态，刷新后恢复原始来源名称。

内容校验流式读取，不把整个文件载入内存，不因去重预先复制源日志。本地导入增加一次完整磁盘读取；远程加入前增加一次完整网络读取，分析时仍需读取，耗时取决于文件大小和网络。校验中检测到大小或修改时间变化时拒绝导入，修正后重试；它不是持续监控或强一致快照，同大小、同修改时间的改写仍可能无法识别。去重针对当前 GUI 列表的导入时内容，不对 CLI 或直接调用分析 API 隐式丢弃文件。

输入路径支持普通绝对/相对路径、成对单双引号、JSON 字符串，以及 `file:///C:/logs/app.log`、`file://localhost/C:/logs/app.log`（Linux 为 `file:///var/log/app.log`）。Windows 支持 UNC 路径和 `file://server/share/app.log`。URI 中空格、中文可使用百分号编码，文件名中的 `#` 必须写为 `%23`；普通路径中的 `#` 无需编码。不支持 HTTP URL。路径属于运行工具的机器；目录与通配符规则同下文。

“输入路径”读取运行 Log Reviewer 的机器上的文件，适合大日志、固定目录和批量匹配，无需先通过浏览器上传。面板显示工具主机、系统和相对路径基准。浏览器与工具部署在不同机器时，应填写工具机器的路径；其他服务器的路径使用“远程获取”。每行一条，点击“添加路径”即校验并展开实际文件，显示匹配与新增数量，再点击“开始分析”。失败时保留输入，提示出错路径和工具工作目录。

支持完整文件路径（如 `C:\logs\app.log`）、目录（如 `/var/log/myapp`）和通配符（如 `C:\logs\*.log`、`/var/log/myapp/app-*.log`）。目录只读取当前层符合“文件设置”的文件，不递归；默认匹配 `.log`、`.txt`、`.text`、`.out`、`.err`、`.trace` 和 `.log.*`。系统目录选择器与浏览器目录导入也使用这些可编辑规则；明确选择单个文件不受目录识别规则限制。通配符支持 `*`、`?` 和字符集合，不支持 `**` 递归。相对路径以工具启动目录为基准，建议使用绝对路径。读取不会修改源文件。已加入的文件标签一行放不下时自动换行。

支持复制来的成对单引号、双引号路径，以及路径中的中文、空格和真实方括号，例如 `C:\logs\[production]\app[01].log`。已存在的文件优先按原样读取；通配符只作用于需要匹配的部分，已有目录名称中的方括号按原样保留。通配符结果中的子目录跳过，不进行递归。一个输入中有错误路径时整批不添加，修正后重试。

| 布局 | 内容 |
| --- | --- |
| 左右 | 分类与事件详情，正文显示在展开事件下 |
| 上下 | 分类在上，详情在下 |
| 上中下 | 分类、事件列表、选中内容纵向排列 |
| 左中右 | 分类、事件列表、选中内容横向排列 |
| 上左右 | 上方分类，下方事件列表和内容 |

布局菜单位于右上角。小屏幕自动纵向排列，选择保存在当前浏览器。界面按日志来源、筛选与导出、总体上下文、分类/事件/内容分组。识别规则与 JSON 报告位于顶部，分析操作在来源区域右侧，单条查询、复制、换行与全屏紧邻日志内容。

日志内容使用离线 Highlight.js 精简核心，标注严重级别、时间、请求 ID、异常类型、堆栈文件与行号，支持文本日志和常见 JSON 级别。Lucide 提供功能图标，悬停显示名称。着色不会改变复制或导出的原文，也不会执行日志中的 HTML。

“自动换行”可切换长行浏览方式。“全屏浏览日志内容”在浏览器页面内展开，可通过 Esc 退出。每个预览最多前 256 KiB 参与着色；如果其中有超过 4096 字符的单行，则回退为原文显示，完整内容和复制不受影响。

内容查询复用 mark.js。正则匹配在独立 Worker 中运行，超过 2 秒自动终止，避免复杂表达式阻塞界面；表达式最多 512 字符。每次最多标注 2000 处，达到上限时计数显示 `+`，可缩小查询范围继续定位。

## 事件与上下文

摘要显示文件名、起始行、日志时间和前 4 KiB 中找到的 `requestId`、`traceId`、`correlationId`；没有这些 ID 时用字节位置定位，不表示业务 ID。时间未知会明确标注。点击后才读取正文和上下文。

GUI 默认启用“自动上下文”，总体前 20、后 100 行是扫描上限，而非必然显示的行数。上限支持 0–10000，修改后离开输入框即自动对所有分类生效并清除单条覆盖。“恢复 20 / 100”恢复默认上限并开启自动模式。取消自动模式后按指定行数读取。

自动范围是透明的启发式：普通错误取少量相邻行；识别到堆栈时适度扩大；连接、超时、重试、事务、内存等提示扩大基础范围。相同请求 ID、同 logger 的相关过程可延伸到扫描上限；另一请求 ID、明显不同线程或相对事件超过 30 秒的日志作为边界，恢复/完成提示结束后文。续行继承所属日志头的请求与时间，避免纳入另一请求的堆栈。时间未知时只使用可观察的其他证据。完整事件始终保留，自动裁剪只作用于额外上下文。

单条工具栏显示“自动上下文”或“自定义上下文”及实际前后行数。修改行数后点“查询”按手动范围读取，覆盖总体自动模式；修改总体设置或恢复默认值会清除单条覆盖。单条覆盖仅保留在当前页面会话，总体设置保存在浏览器。自动结果不是因果证明：缺少 ID、复用线程、长于 30 秒的请求可能需要手动扩大范围。

时间片段导出位于右上角 JSON 报告旁，使用筛选栏的开始、结束时间。分析及导出期间显示遮罩，完成或失败后自动关闭；分析时可以在遮罩中取消任务。

CLI 保持默认手动行为，显式添加 `--auto-context` 启用同一推断：

```sh
log-reviewer query --report report.json --group GROUP_ID --details --auto-context --before 20 --after 100
```

关键字/正则查询时上下文围绕首次匹配行，另附完整事件以保留堆栈。无文本条件时围绕完整事件。正文及各方向上下文有 2 MiB 显示上限，完整内容可导出。

## 时间片段

GUI 先分析文件，选开始/结束时间，再选“合并日志”或“分文件 ZIP”，点击“导出时间片段”。使用时间和文件范围条件，忽略关键字、正则、分类、级别过滤；未勾选 INFO 也能导出普通日志。

```sh
log-reviewer export-time --report report.json --from '2026-10-14T12:30:00+08:00' --to '2026-10-14T12:35:00+08:00' --out nodes.txt
log-reviewer export-time --report report.json --from '2026-10-14T12:30:00+08:00' --to '2026-10-14T12:35:00+08:00' --out-dir nodes-period
```

`--source N` 指定零基文件索引。CLI 输出文件/目录必须不存在，避免覆盖日志。分文件名为 `序号-日志文件-开始时间-结束时间.log`，非法字符替换为 `_`，序号避免多节点同名冲突。

按报告 `sources` 顺序合并，不按跨节点时间重排。合并保留原始字节，仅在文件边界缺少换行时补换行；分文件原样保留。无时间续行继承前一条可识别时间，因此包含堆栈；文件开头的无时间内容排除。无时间独立日志也会继承前一时间，这是缺少时间信息时的限制。可处理时间乱序。扫描使用内置格式，不继承分析时临时传入的自定义日志头规则；无法识别的特殊时间格式需先转换。

结束秒、分钟、日期包含整个精度范围，显式小数按精确边界。GUI 使用浏览器时区，CLI 无时区时间使用工具机器时区，多节点建议显式写时区。导出重新流式扫描并校验快照；源日志追加、轮转或替换后应重新分析。缓存磁盘需容纳临时导出和 ZIP。

Chrome / Edge 可流式保存大文件；其他浏览器超过 256 MiB 时请使用 CLI。

## SSH 信任目录

```sh
log-reviewer fetch --host 192.168.1.20 --user deploy --path /var/log/app --ssh-dir /home/deploy/.ssh --key /home/deploy/.ssh/id_ed25519 --analyze
```

SSH 端口默认 22。未指定指纹或 `--known-hosts` 时读取指定目录的 `known_hosts`，未指定目录则使用运行账户的 `~/.ssh/known_hosts`。GUI 路径指向**工具所在机器**，不是访问网页的电脑。

保留 OpenSSH 的端口匹配、散列主机与密钥校验；文件缺失、密钥不匹配、未知主机均拒绝连接。指定目录不自动读取私钥或 SSH config，认证私钥仍由 `--key` 或 GUI 提供。不自动信任未知主机。
