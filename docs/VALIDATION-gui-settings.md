# GUI 设置与启动入口回归

日期：2026-10-15。环境：Windows amd64、Go 1.25.3、Chrome 独立 CDP context、Playwright。

## 修复与审查

- 原设置弹窗将两个独立保存区域上下拼接，导致出现两个没有区分范围的“保存”按钮。现在通过“访问控制”“文件与分析”页签明确保存范围，每次只显示一个保存入口。
- 弹窗标题和页签固定；内容独立滚动，底部操作区保持可达。检查了 1920×920、1440×900、768×650、390×844、390×480，无横向溢出或保存按钮越界。
- Windows 双击和无参数启动沿用 `run -> gui(nil)`，默认显示“上传文件”和“选择路径”。上传始终存在；`--show-file-picker` 或 `--show-path-input=false` 切换为部署机器文件选择。两个部署文件入口互斥，同时启用时文件选择优先。浏览器回归使用等价的 `gui` 入口并添加本机监听、随机端口和禁止自动开浏览器参数。
- 清理了旧的隐藏文件设置弹窗代码；保存时禁止重复提交、关闭弹窗和切换页签，失败后恢复操作。设置加载成功后才启用文件保存，token 验证成功后重新加载文件配置。
- 代码审查检查了参数优先级、页签键盘访问、错误恢复、目录迁移后的来源映射及旧测试与当前功能约定的差异。

## 复现与边界

配置 `NODE_PATH` 指向已有 Playwright 包，Chrome 独立调试 Profile 监听 `127.0.0.1:9222`，例如执行：

```powershell
$env:LR_TEST_BINARY = (Resolve-Path .\dist\log-reviewer-windows-amd64.exe).Path
node tests/ui-settings-regression.cjs
node tests/gui-smoke.cjs
```

远程失败重试脚本需要通过 `LR_TEST_URL` 提供已启动的本机 HTTP URL，包含会话 token。原生系统选择器用 API 模拟响应与服务端测试验证，未自动点击真实 Windows 文件对话框；真实双击自动打开浏览器也未执行，以免要求证书或其他交互确认。其他平台只有构建验证。截图位于系统临时目录中的 `lr-settings-regression-*`，修复前备份位于 `lr-fix-20261015-175424`。
